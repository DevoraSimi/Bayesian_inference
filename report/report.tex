\title{Bayesian and Neural Approaches to Word-Level Language Modeling:\\
A Comparative Study on the Sherlock Holmes Corpus}
\author{Devora Simi}
\date{\today}

\begin{document}
\maketitle

\begin{abstract}
We study next-word prediction on a corpus of Arthur Conan Doyle's Sherlock
Holmes novels and short stories as a controlled setting for comparing
statistical language models that make different commitments to Bayesian
inference. We implement and evaluate four model families on identical
train/validation/test splits: (i) an $n$-gram Markov model with
hierarchical Dirichlet smoothing, in which each context's next-word
distribution has a Dirichlet prior centred on the next-shorter context's
distribution, so that the smoothed estimate is exactly a Bayesian posterior
predictive; (ii) a discrete-emission Hidden
Markov Model (HMM) fit by maximum-likelihood/MAP Baum-Welch EM, i.e.\ a
point-estimate latent-variable model; (iii) a fully Bayesian variant of the
same HMM fit by mean-field Variational Bayes EM (VB-EM), which maintains
Dirichlet \emph{posterior distributions} over the initial-state,
transition, and emission parameters rather than point estimates; and (iv)
a long short-term memory (LSTM) recurrent neural network language model, used both as a
point-estimate neural baseline and, via Monte Carlo Dropout, as an
approximate Bayesian neural model with predictive uncertainty. All models
are evaluated on held-out perplexity and top-$k$ next-word accuracy, the
latter reported both over all tokens and restricted to real words (i.e.\
excluding punctuation tokens). This report documents the problem
formulation, data pipeline, and modeling/evaluation methodology.
\emph{Experimental results are not yet included.}
\end{abstract}

\section{Problem Statement}
% ============================================================

The task is \textbf{word-level next-token prediction}: given a prefix of
tokens $w_1, \dots, w_{t-1}$ from a paragraph, predict a distribution over
the next token $w_t$ from a fixed vocabulary. This is the same underlying
predictive-text task that powers autocomplete and keyboard-suggestion
systems, and it is a convenient testbed for a broader question: \emph{how
much does the choice of Bayesian inference strategy matter for the same
modeling task and the same data?}

Rather than comparing unrelated model families, we deliberately structure
the comparison as three points on a single spectrum of how much
uncertainty a model represents over its own parameters:

\begin{enumerate}
    \item \textbf{Point estimation with a Bayesian smoothing prior.} The
    $n$-gram model and the standard HMM both use a Dirichlet prior only to
    regularize a single point estimate of their parameters (posterior mean
    or MAP), never propagating parameter uncertainty forward.
    \item \textbf{Full posterior inference.} The Variational Bayes HMM
    places the same conjugate Dirichlet priors on the same parameters as
    the point-estimate HMM, but maintains and updates full posterior
    distributions over them via mean-field VB-EM, so that predictions
    integrate over parameter uncertainty rather than plugging in a single
    value.
    \item \textbf{Approximate Bayesian deep learning.} The long short-term
    memory (LSTM) network~\cite{hochreiter1997} has no
    tractable parameter posterior, but Monte Carlo Dropout (Gal and
    Ghahramani, 2016) is used to approximate Bayesian model averaging over
    an implicit posterior over its weights, at prediction time.
\end{enumerate}

Holding the task, data, and evaluation protocol fixed lets us ask, for
each pair of models, whether the extra machinery of full or approximate
Bayesian inference actually changes predictive performance (perplexity,
top-$k$ accuracy) and/or yields useful predictive uncertainty, relative to
the corresponding point-estimate model.

A secondary, applied framing of the same task is a \textbf{predictive-text
/ autocomplete demo}: given a typed prefix, suggest the top-$k$ most
likely next words under each trained model (and, for the RNN, an
uncertainty estimate per suggestion via MC Dropout).

\section{Data}
% ============================================================

\subsection{Source corpus}

The corpus is the complete Sherlock Holmes canon by Arthur Conan Doyle: nine public-domain works obtained from Project Gutenberg~\cite{doyle}, consisting of four novels and five short-story anthologies.

\begin{itemize}
    \item Novels: {A Study in Scarlet}, {The Sign of Four},
    {The Hound of the Baskervilles}, {The Valley of Fear}.
    \item Anthologies: {The Adventures of Sherlock Holmes},
    {The Memoirs of Sherlock Holmes}, {The Return of Sherlock
    Holmes}, {His Last Bow}, {The Case-Book of Sherlock Holmes}.
\end{itemize}

\subsection{Preprocessing pipeline}

Preprocessing (\texttt{src/preprocess.py}, \texttt{src/data\_utils.py})
follows the WikiText benchmark conventions~\cite{merity2016}, which use
the Moses tokenizer~\cite{koehn2007}:

\begin{enumerate}
    \item \textbf{Boilerplate removal.} Project Gutenberg license headers
    and footers are stripped.

    \item \textbf{Unit segmentation.} Anthologies are split into stories
    by locating each title from the ``Contents'' listing in the body text;
    novels stay whole. This gives 60 units: 56 stories and 4 novels.

    \item \textbf{Paragraphs.} Each sequence is one paragraph (text
    between blank lines), ending with \texttt{<eos>}; there is no sentence
    splitting.

    \item \textbf{Heading removal.} Titles, chapter headings, contents
    listings and bylines are dropped (WikiText keeps section titles; here
    they are layout, not content).

    \item \textbf{Normalization.} Variants of the same symbol are unified
    (e.g., curly/straight quotes).

    \item \textbf{Tokenization.} Case is kept, every punctuation mark is a
    token, and numbers are kept. Clitics are split (\texttt{don 't},
    \texttt{Holmes 's}), inner hyphens and number separators become markers
    (\texttt{well @-@ known}, \texttt{1 @,@ 000}), and title abbreviations
    stay whole (\texttt{Mr.}, \texttt{Dr.}).

    \item \textbf{Leak-free splitting.} Whole units are assigned to splits,
    so no story appears in two splits. Units are shuffled and
    filled into test, validation, then train, until each reaches its token
    target (10\%, 10\%, rest).

    \item \textbf{Vocabulary.} Built from the training split only: every
    token seen at least twice (WikiText uses three; this corpus is smaller so we used two), plus \texttt{<unk>} and
    \texttt{<eos>}.
\end{enumerate}

% ============================================================
\section{Models}
% ============================================================

All four model families are trained and evaluated on the same encoded
paragraphs, each ending in \texttt{<eos>} (for the RNN, the same
paragraphs concatenated into one token stream), and share the same
vocabulary, so every model predicts the same tokens and their outputs are directly comparable.

\subsection{$n$-gram model with hierarchical Dirichlet smoothing}

The simplest model tested is the n-gram model, which predicts the next word from the $n-1$ words before it,
using counts from the training data. Raw counts give probability zero to
any word never seen after a context, so we smooth them with the
hierarchical Dirichlet scheme of MacKay and Peto~\cite{mackay1995}. Let
$h_k$ be the last $k$ words of the context and
$c(h_k, w) = \sum_t \mathbf{1}\big[(w_{t-k}, \dots, w_{t-1}) = h_k,\ w_t = w\big]$
the number of times $w$ followed $h_k$ in training, with
$c(h_k) = \sum_w c(h_k, w)$. Then
\[
P_k(w \mid h_k) = \frac{c(h_k, w) + \alpha\, P_{k-1}(w \mid h_{k-1})}
{c(h_k) + \alpha}, \qquad P_{-1}(w) = \frac{1}{V},
\]
so the trigram estimate is pulled toward the bigram, the bigram toward the
unigram, and the unigram toward uniform. This is the posterior mean (and,
by conjugacy, the posterior predictive) under a prior
$\theta_{h_k} \sim \text{Dirichlet}\big(\alpha\, P_{k-1}(\cdot \mid
h_{k-1})\big)$ on each context's next-word distribution.

Here $\alpha$ is the prior's total pseudo-count mass: a context's own
counts get weight $c(h_k)/(c(h_k) + \alpha)$, so frequent contexts follow
their data while rare or unseen ones fall back on the shorter context.
Plain additive smoothing is the special case where every context is
smoothed straight toward uniform; with it, rare trigram contexts fall
back to a near-random guess, and a trigram model did worse than a bigram.
The model trains in a single counting pass and is fully interpretable,
but it sees only the last $n-1$ words and cannot generalise across
similar contexts. Implemented in \texttt{src/ngram.py}.

\textbf{Hyperparameters explored:} order $n$ (context length) and the
prior concentration $\alpha$.

\subsection{Hidden Markov Model (point estimate)}

Instead of a fixed window of $n-1$ words, an HMM carries the whole
history as a belief over $N$ hidden states. Each word $w_t$ is emitted by
a hidden state $z_t$, with initial distribution $\pi$, transitions
$A_{ij} = P(z_{t+1} = j \mid z_t = i)$ and emissions
$B_{jw} = P(w_t = w \mid z_t = j)$.

The states are unobserved, so we track
$\alpha_t(j) = P(z_t = j \mid w_{1:t})$ with the forward algorithm:
\[
\alpha_t(j) = \frac{1}{c_t}\, B_{j w_t} \sum_i \alpha_{t-1}(i) A_{ij},
\qquad c_t = P(w_t \mid w_{1:t-1}),
\]
starting from $\alpha_1(j) \propto \pi_j B_{j w_1}$. The normaliser $c_t$
prevents underflow and gives $\log P(w_{1:T}) = \sum_t \log c_t$. To
predict the next word we move the belief one step forward and emit:
$P(w_{t+1} = w \mid w_{1:t}) = \sum_{i,j} \alpha_t(i) A_{ij} B_{jw}$.

We train with Baum-Welch (EM). The E-step uses forward-backward to get
the expected state and transition counts,
$\gamma_t(i) = P(z_t = i \mid w_{1:T})$ and
$\xi_t(i,j) = P(z_t = i, z_{t+1} = j \mid w_{1:T})$. The M-step normalises
these counts, with an additive smoothing term $\epsilon = 10^{-3}$, e.g.
\(
A_{ij} = \frac{\sum_t \xi_t(i,j) + \epsilon}{\sum_{t<T} \gamma_t(i) + N\epsilon},
\)
and analogously for $B$ and $\pi$. The smoothing prevents zero
probabilities for transitions or emissions that receive zero expected
counts. The resulting model is a point estimate of $\pi$, $A$, and $B$,
with no posterior uncertainty over these parameters, which the VB-HMM
below addresses.
Parameters are randomly initialised to break symmetry between the
hidden states, and EM finds only a local optimum. Implemented in
\texttt{src/hmm.py}.

\textbf{Hyperparameters explored:} number of latent states $N$.

\subsection{Variational Bayes HMM (full posterior)}

The HMM above keeps a single value for each parameter, so it cannot tell
a transition seen once from one seen a thousand times. The VB-HMM keeps
the same model but puts Dirichlet priors on the parameters,
$A_{i\cdot} \sim \text{Dir}(\alpha_0)$, $B_{j\cdot} \sim \text{Dir}(\beta_0)$,
$\pi \sim \text{Dir}(\pi_0)$, and fits an approximate posterior
$q(z)\,q(\pi, A, B)$ by mean-field Variational Bayes~\cite{beal2003,bishop2006}.

By conjugacy the posterior stays Dirichlet, so the M-step just adds the
expected counts to the prior, e.g.\
$\hat\alpha_{ij} = \alpha_0 + \sum_t \xi_t(i,j)$. The E-step is the same
forward-backward, but with each parameter replaced by
\[
\widetilde{A}_{ij} = \exp\big(\mathbb{E}_q[\log A_{ij}]\big)
= \exp\Big(\psi(\hat\alpha_{ij}) - \psi\big(\textstyle\sum_k \hat\alpha_{ik}\big)\Big),
\]
where $\psi$ is the digamma function. For large counts this is close to
$\hat\alpha_{ij} / \sum_k \hat\alpha_{ik}$, but for small counts it is
smaller, so rare transitions,
emissions and states are down-weighted automatically. Training maximises
the ELBO, $\sum_t \log \widetilde{c}_t - \mathrm{KL}(q \,\|\, p)$, which
never decreases, and stops when its relative change is below $10^{-4}$.
For prediction we use the posterior mean
$\hat\alpha_{ij} / \sum_k \hat\alpha_{ik}$, so the model plugs into the
same forward filter as the HMM. Implemented in \texttt{src/vb\_hmm.py}.

\textbf{Hyperparameters explored:} number of latent states $N$ (matched to
the HMM sweep). The priors are fixed at $\alpha_0 = \pi_0 = 1$ (uniform)
and $\beta_0 = 0.1$ (sparse emissions).

\subsection{LSTM recurrent neural network}

Like the HMM, the LSTM~\cite{hochreiter1997} carries the history in a
state updated one word at a time, but the state is a learned continuous
vector rather than a belief over discrete states. Each token is mapped to
a learned embedding $e_t$, and the LSTM keeps a hidden state $h_t$ and a
memory cell $c_t$, controlled by forget, input and output gates:
\[
\begin{aligned}
f_t, i_t, o_t &= \sigma\big(W_{f,i,o}\, e_t + U_{f,i,o}\, h_{t-1} + b_{f,i,o}\big),
\qquad g_t = \tanh(W_g e_t + U_g h_{t-1} + b_g), \\
c_t &= f_t \odot c_{t-1} + i_t \odot g_t, \qquad h_t = o_t \odot \tanh(c_t).
\end{aligned}
\]
The forget gate decides how much of the old memory to keep, while the
input gate decides how much of the candidate content $g_t$ to write to
the cell. Because $c_t$ is updated
additively, information and gradients can propagate across many time steps, helping to alleviate the vanishing-gradient problem of plain RNNs. With two layers,the second LSTM layer takes the first layer's hidden state at each time step as input. A linear layer maps the top $h_t$ to the next-word
distribution,
\[
P_\theta(w_{t+1} = w \mid w_{1:t}) = \mathrm{softmax}(W_{\text{out}} h_t + b_{\text{out}})_w ,
\]
where $\theta$ denotes all model parameters.

Dropout is applied to the embeddings and to the LSTM outputs (and between
layers when there are two). Similar contexts can lead to similar hidden
states, allowing information learned from one context to generalize to
others rather than relying only on exact count matches.

The paragraphs are concatenated into one stream, split into $B = 20$
parallel rows (the batch size), and processed in windows of $L = 30$
tokens (truncated BPTT), so each mini-batch is $B \times L$ tokens. On
each mini-batch we minimise the cross-entropy loss, which with a single
true next token is its average negative log-probability,
\[
\mathcal{L}(\theta) = -\frac{1}{BL}\sum_{b=1}^{B}\sum_{t=1}^{L}
\log P_\theta\big(w^{(b)}_{t+1} \mid w^{(b)}_{\le t}\big),
\]
where $w^{(b)}_{\le t}$ denotes the preceding tokens available to the
model in row $b$, and take one Adam step, with the gradient norm clipped at $0.25$.
The hidden state at the end of a window is passed on to the next one, so
the forward context is not limited to the window; only the gradients are cut
there, so gradients are propagated back at most 30 steps. We stop
early when validation perplexity has not improved for 5 epochs and keep
the weights of the best epoch. The result is a single point estimate
$\hat\theta$ of the weights. Implemented in \texttt{src/rnn.py}.

\textbf{Hyperparameters explored:} in two steps. First, embedding size,
dropout and learning rate are tuned with Optuna's TPE
sampler~\cite{akiba2019} (\texttt{src/tune\_rnn.py}): 50 trials of up to
40 epochs each, with the same early stopping, each scored by its best
validation perplexity; the best configuration is then retrained for up
to 50 epochs. The search runs at a fixed hidden size
(128) and one layer. Second, with those three values fixed, a grid
over hidden size and number of layers (\texttt{src/experiment.py}).

\subsubsection{Monte Carlo Dropout}

The LSTM has no tractable posterior over its weights. Gal and
Ghahramani~\cite{gal2016} showed that training with dropout is
approximate variational inference, where $q(\theta)$ is the distribution
of weights produced by random dropout masks. So at test time we keep
dropout on and average $M$ forward passes, each with a fresh mask
$\theta_m \sim q(\theta)$:
\[
\bar P(w \mid w_{1:t}) = \frac{1}{M}\sum_{m=1}^{M} P_{\theta_m}(w \mid w_{1:t})
\;\approx\; \int P_\theta(w \mid w_{1:t})\, q(\theta)\, d\theta .
\]
Perplexity is computed from $\log \bar P$ at the true token, not from the
mean of $\log P_{\theta_m}$: that would score the individual samples
rather than their average, and by Jensen's inequality it is always worse.
The spread across passes, $\sigma(w) = \operatorname{std}_m
P_{\theta_m}(w \mid w_{1:t})$, measures how uncertain the model is about
each word; with no dropout all passes agree and $\sigma = 0$.

Nothing is retrained: the same weights are scored, only the prediction
changes. We use it in two places. \texttt{evaluate\_rnn\_mc\_dropout}
re-scores each trained model for several values of $M$ (e.g.\ 5, 20,
50), to see whether averaging improves perplexity and accuracy and how
many passes it takes to converge. \texttt{predict\_demo.py} shows each
suggested word with $\bar P$ and $\sigma$. Implemented in
\texttt{src/rnn.py} and \texttt{src/evaluation.py}.

\section{Evaluation Protocol}
% ============================================================

All four model families are scored with the same two metrics
(\texttt{src/evaluation.py}), computed identically (up to each model's
own notion of ``predict from the prefix seen so far'') across models:

\begin{itemize}
    \item \textbf{Perplexity:} $\exp\!\big(-\tfrac{1}{T}\sum_t \log
    P(w_t \mid w_{<t})\big)$ over all tokens in the evaluation split,
    including each sequence's first token (predicted from an empty/short
    context -- the $n$-gram model's shortest-available context, or the
    HMM's initial-state distribution).
    \item \textbf{Top-$k$ accuracy}, $k \in \{1, 5, 10\}$: whether the
    true next token is among the model's $k$ highest-probability
    predictions, computed incrementally (predict, then reveal the true
    token and update state) and \textbf{not} scored on each sequence's
    first token (no prior context to predict from).
\end{itemize}

Because punctuation tokens are highly predictable from local context (and
would inflate accuracy for any model that learns punctuation patterns
well), top-$k$ accuracy is reported \textbf{twice}: once over all tokens,
and once restricted to positions whose true next token is a real word
(i.e.\ excluding the punctuation subset of the vocabulary). The
words-only variant is the more meaningful measure of actual next-word
prediction quality.

All models are evaluated on the same validation and held-out test
splits described in Section~2.

\section{Experimental Design}
% ============================================================

\texttt{src/experiment.py} runs a grid sweep over all four model
families on identical data splits, saving a checkpoint (model
weights/parameters, training config, and validation/test metrics) per
configuration for reproducibility:

\begin{itemize}
    \item \textbf{$n$-gram:} grid over order $n \in \{2, 3\}$ $\times$
    prior concentration $\alpha \in \{10, 30, 100\}$ (defaults of
    \texttt{experiment.py}).
    \item \textbf{HMM and VB-HMM:} grid over number of latent states,
    with the \emph{same} state-count grid used for both, enabling a
    direct MAP-EM vs.\ VB-EM comparison at matched capacity; VB-HMM prior
    concentrations held fixed.
    \item \textbf{LSTM:} grid over hidden size $\times$ number of layers,
    with embedding size, dropout and learning rate fixed to the Optuna
    result, each trained with early stopping on validation
    perplexity; optionally, each trained configuration is additionally
    re-evaluated with MC Dropout at several sample counts to study
    convergence of the Bayesian model average.
\end{itemize}

Separately, \texttt{src/tune\_rnn.py} runs an Optuna TPE search over
embedding size, dropout, and learning rate at a fixed architecture size,
then retrains the best configuration with a longer budget and early
stopping.

Every configuration of every model is evaluated with the identical
protocol of Section~4 on the identical held-out test split, so that
perplexity and top-$k$ accuracy are directly comparable model-to-model
and not just within a model family. The ``best'' configuration of each
model family is selected by \emph{validation} perplexity, and its test
metrics are then reported; the test split is never used for selection,
which would bias the reported test numbers optimistically.
